Modelfiche workflow quality audit

The product model and visual identity are strong. The app clearly separates workspace, projects, datasets, runs, models, evaluations, grids, and operations. It is not yet at the Impeccable Craft production bar: keyboard focus barriers, unsafe batch-preview state, endpoint/schema drift, unbounded comparison density, and narrow-screen composition create major failures in the core operator journeys.

Recommended remediation sequence

Phase 1 · Trust & access

Make navigation and actions honest

  • Modal drawer/lightbox primitives with inert background and focus lifecycle.
  • Route transition policy: push → top/H1; pop → prior scroll/focus.
  • Skip links, labelled landmarks, native links/listbox/radiogroup patterns.
  • One route-level loading/error state; suppress false “Unknown” and duplicate alerts.
Phase 2 · Data integrity

Repair the golden paths

  • Dataset pagination/virtualization and caption-format correctness.
  • Preview tokens bound to draft, selection, format, and inputs; add undo/history.
  • Repair Prompt Set API and connect saved versions to Eval/Grid.
  • Generate Grid fields/axes/bounds solely from endpoint schemas.
Phase 3 · Comparison ergonomics

Bound density and preserve context

  • Transpose Samples: prompt rows × checkpoint-step columns.
  • Virtualize Eval/Sample/Gallery/Dataset; composite rating controls.
  • Purpose-built mobile summary/detail views for Queue and comparisons.
  • Semantic Grid with sticky headers, zoom/fit/pan, keyboard scan.
Phase 4 · Operations

Expose consequences before work

  • Mandatory S3 detection preview and constrained prefixes.
  • Export privacy/size/destination review; cost/risk review for generation.
  • Health matrix with worker/provider/source freshness.
  • Human failed-job summary, Retry, diagnostics disclosure, lifecycle activity.

Actionable recommendation register

P1 · R01

Build one accessible focus-workspace primitive

Mobile navigation, metadata drawers, and the image lightbox visually obscure the app but leave background controls focusable. Direct lightbox entry focuses BODY; Escape often loses the opener.

Impact
Keyboard and screen-reader users can operate hidden UI and lose their place.
Action
Move focus on open, inert the background, contain Tab/Shift+Tab, Escape/backdrop close, restore opener. Use labelled dialog semantics or a true dedicated review route.
Acceptance
Automated keyboard path for both drawers and image review at 390 px; accessibility snapshot contains only the active focus workspace.

Define route focus and scroll restoration

New routes inherit unrelated scroll coordinates and hide their H1; collapse/reopen controls are replaced and lose focus.

Action
Push navigation focuses the new H1/main and scrolls to top; browser Back restores previous scroll/focus. Keep rail toggles mounted or focus their replacements.

What already works

Distinct product identity

Cobalt archival workbench, squared geometry, technical labels, coherent light/dark themes, and image-led surfaces avoid generic AI/SaaS ornament.

Clear top-level model

Dashboard, Projects, Gallery, Runs, Models, Datasets, Evals, Grids, Queue, Transfers, and Settings mostly read as distinct layers.

Strong visible focus

Sampled controls consistently showed a high-contrast outline/ring. Active navigation exposes aria-current and status uses text, not color alone.

Good draft vocabulary

Current, published, Draft, Editing, Working draft, selection counts, and before/after preview make dataset state understandable.

Good desktop Eval comparison

Four checkpoints × three prompts align cleanly with step labels and contained media; dedicated Grid review avoids ratings/comments/sidebar.

Credential and mutation restraint

Credentials are write-only; several unsafe or invalid actions are disabled; no audited page triggered intentional billable work.

No page overflow

All representative routes kept document width within 1440 and 390 px. The remaining problem is quality of internal scrollers and narrow composition.

Reduced motion and theming

Theme toggle is named, pressed-state aware, persistent, and coherent. Reduced-motion preference reduces transitions to effectively instant.

Method, safety, and limitations

Audit execution

Six OpenAI Codex subagents executed independent Playwright/browser stories in parallel: navigation, datasets, models/runs, evals/grids, operations/settings, and cross-cutting accessibility. The synthesis applied Impeccable Shape (primary action, state model, interaction flow, content, constraints, anti-goals) and Craft (semantic controls, complete states, keyboard/touch, responsive composition, technical cleanliness) criteria.

  • No intentional billable actions: no FAL generation, prompt/caption generation, Eval/Grid admission, RunPod training, OpenRouter generation, upload/hydration, import, export, rating/comment/decision save, or provider validation.
  • No record mutations: only read-only route inspection plus harmless theme/rail preferences, restored where exercised.
  • Observed caveat: Settings appeared to auto-load a provider catalog on route entry; this unrequested external behavior is flagged as OPS-10.
  • Evidence boundary: billing outcomes, destructive confirmations, retry success, true running progress, and post-submit announcements were not tested.
  • DESIGN.md caveat: individual auditors reported it unavailable in their isolated snapshots. The orchestrator loaded the repository DESIGN.md and used its explicit requirements—Cobalt Xerox identity, semantic tokens, responsive rails, dedicated review workspaces, keyboard focus, vertical page scrolling, and project-contained Datasets/Evals—in this synthesis.
  • Performance: findings use observed DOM/image/focus counts and page extents, not Lighthouse or laboratory profiling.
