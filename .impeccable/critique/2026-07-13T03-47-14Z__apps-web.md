## Anti-Patterns Verdict

**LLM assessment — pass, not generic AI slop.** Desktop light and dark surfaces are recognizably ModelFiche: the paper/cobalt and observatory themes, catalog numbering, square ruled panels, specimen mosaics, loss charts, reader symbols, and technical rails all reinforce a visual-training archive rather than a generic SaaS dashboard. The risk is information dumping, not generic styling: default-expanded training runs, long eval histories, and unexplained system constraints compete with the next action.

**Deterministic scan — source-clean but rendered-shell findings remain.** All six source-target CLI scans returned `[]`. Runtime detector injection succeeded in fresh light and dark tabs for every reviewed route. It consistently surfaced the intentionally designed grid/scanline texture, inspector grouping, and compact profile selector; those are expected false positives. It also surfaced valid accessibility/debt signals: 20 activity entries at 10px on each full-shell route; Model light mode has visible `#6573a4` on `#f2f4fa` at 4.2:1 in training metadata and captions; project/model table wrappers become cramped; Model dark breadcrumbs overflow at one desktop width. Runtime detector findings are page-wide, so shell results are not source-local defects in each TSX target.

**Visual overlays.** Detector overlay injection rendered banners and labels on each representative [Human] assessment tab. The detectors highlighted body texture, metadata cards, profile selector, activity text, and table wrappers. Live detector servers were stopped; no source files were modified.

## Overall Impression

The desktop product feels like a serious, distinctive archive workbench. The single biggest opportunity is to make that competence available at the point of action: repair mobile shell geometry, then turn hidden generation constraints into visible preflight guidance instead of post-submit failure.

## What’s Working

1. **A coherent product identity.** The two semantic themes are materially different but preserve hierarchy; the theme control correctly changes its pressed state and visual asset variants.
2. **Domain-specific visual hierarchy.** Project/model pages put specimen imagery, loss evidence, run facts, versions, and lineage into a credible operator workflow. The grid composer’s X/Y/Z model is a real technical affordance, not decorative UI.
3. **Good baseline system status.** Status chips, queue notices, metadata totals, activity records, loading/error/empty states, and project/run navigation provide dependable orientation on desktop.

## Priority Issues

### [P0] Mobile shell hides every route’s first actionable frame
**Evidence.** At 390×844 on dashboard, project, and model, `.vela-sidebar` remained 390×844 while its navigation was hidden; the topbar began at y=844 and main content at y=904. Base CSS sets `block-size: 100vh/100dvh` (`apps/web/src/vela-theme.css:134-143`), but the ≤680px rule only sets `height:auto` (`:326-344`) and therefore does not reset the logical block size.

**Why it matters.** A mobile user initially sees a blank branded rail and cannot reach navigation, theme, create, metadata, or page content. This is a functional failure across the product, not a cosmetic responsiveness issue.

**Fix.** At the mobile breakpoint explicitly reset `block-size:auto` (and any min-block-size) for the static sidebar; verify the topbar begins in the first viewport in both themes and route families. Preserve drawer semantics after geometry is corrected.

**Suggested command:** `/impeccable adapt apps/web`

### [P1] Generation builders reveal prerequisites too late and permit a known-invalid action
**Evidence.** Grid initially shows “Grid incomplete / Select a fixed model/checkpoint” but leaves **Generate grid** actionable. `grid.ts` rejects duplicate/empty axes and invalid model/Z combinations only at compile time. The image generator can initialize model scope only via URL/prefill — no normal Scope control is rendered — hard-codes one output, and exposes a read-only queue. Eval eligibility is shown only after project selection; endpoint/FAL reasons are dispersed across disabled picker items.

**Why it matters.** Creators cannot predict whether they can run, how many cells/outputs they will create, or why controls are unavailable. Failed submits and implicit constraints destroy confidence precisely when compute/cost is at stake.

**Fix.** Render a preflight block next to the primary action: selected project, eligible checkpoint, prompt/axis validity, prospective output/cell count, size/cost/provider warning, and the exact next missing requirement. Disable Generate until it is satisfied. Add visible Image scope, editable batch count when supported, reset/clear controls, inline numeric constraints, examples for newline axis syntax, and queue cancel/retry/open-result actions.

**Suggested command:** `/impeccable clarify apps/web`

### [P1] Dense metadata violates legibility and table discovery on narrow surfaces
**Evidence.** Every reviewed shell route renders twenty activity metadata paragraphs at 10px. Model light mode has 53 detector low-contrast hits, including visible training labels/captions at 4.2:1. Project and Model mobile tables measure 620px wide inside a 390px viewport; Project’s Eval table is clipped by page-level overflow and exposes only part of the row without a visible local-scroll affordance. The model page also has a 119-character description line and tiny `small` text.

**Why it matters.** High-value provenance, status, and table fields are the core of an archive workbench. Making them technically present but difficult to read or discover is an integrity failure.

**Fix.** Raise activity/metadata text to the documented readable small step, adjust the light muted token until visible text meets 4.5:1, constrain prose measure, and make every overwide table explicitly horizontally scrollable with an affordance/fade/label. On mobile, prioritize summary columns and let users reveal secondary fields rather than silently clipping them.

**Suggested command:** `/impeccable typeset apps/web`

### [P2] Long model/eval pages overload review instead of progressively disclosing it
**Evidence.** Model at 390px is about 6,619px tall; two training runs are expanded by default, each including facts, charts, nine samples, and configuration disclosure. Eval is about 3,734px tall and repeats large preview cards plus long provider/checkpoint strings. Grid is 2,859px on mobile and retains two 173px X/Y axis cards.

**Why it matters.** Reviewers must sift through unrelated data before reaching the next decision. Small mobile axis editors make a complex task more error-prone.

**Fix.** Collapse historical training runs by default after a concise summary; retain the latest run expanded. Group eval history into an inspectable table/summary. Stack Grid X/Y editors below 680px while keeping the finished board locally scrollable. Move raw provider IDs behind a copyable technical disclosure.

**Suggested command:** `/impeccable distill apps/web`

### [P2] Dashboard and queues need actionable workspace control
**Evidence.** Dashboard cards are single large links with no local filtering/sorting or secondary actions; archived-project fallback can silently display archived projects. Image queues display status/progress/error but offer no cancel, retry, or open-result affordance.

**Why it matters.** Operators can orient themselves, but cannot efficiently triage or recover work from the interface that reports it.

**Fix.** Add explicit dashboard filtering/sort state and an archived-state explanation; add queue actions appropriate to lifecycle state with confirmation for destructive actions.

**Suggested command:** `/impeccable harden apps/web`

## Persona Red Flags

**Creative operator.** On Image/Grid/Eval generation, they must infer eligibility, batch/cell volume, parameter syntax, and compute readiness from disabled controls or a submit-time alert. The first failed **Generate grid** interaction is preventable.

**Model trainer/reviewer.** On mobile, the first viewport is empty shell chrome. After reaching content, 10px activity history, low-contrast training labels, and clipped 620px tables make provenance and checkpoint review harder than the desktop evidence demands.

**Production lead.** The queue reports state but offers no recovery; no preflight exposes expected cell/output count, provider readiness, or cost/risk. Large grid admissions can surprise the operator.

## Minor Observations

- The compact profile control intentionally clips its enlarged native select; detector flags it, but it is currently a deliberate affordance. Protect it with a browser interaction test before changing it.
- Grid/body texture and inspector “nested card” findings are intentional product language, not generic generated decoration.
- Model dark breadcrumbs overflow at one observed desktop width; enforce truncation or a responsive breadcrumb pattern.
- Repeated “View all” links should include their target in accessible names.
- The code’s `vela-*` compatibility namespace is not user-facing; do not spend priority budget renaming it.

## Questions to Consider

- Can the product promise “no compute submit without a visible preflight” as a cross-generator invariant?
- Which review evidence must remain visible by default: latest run, selected checkpoint, or outputs? Everything else can be progressive disclosure.
- Should mobile tables become condensed records with a “technical columns” disclosure rather than relying on horizontal scrolling?
